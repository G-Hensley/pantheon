# Lexicon lifecycle setup

Pantheon opts into Lexicon's AI Development Life Cycle through the
[Life Cycle block](../../AGENTS.md#life-cycle). The tracked `.agents/` directory
contains the portable skills, agent definition, schemas, and installation ledger.
This setup supports future app work; it does not implement the remaining fleet
features or establish that their acceptance criteria hold.

The [tracker activation checkpoint](../github-issues.md#activation-checkpoint)
still governs tracker authority and pickup. Lifecycle adoption does not activate
the staged GitHub handoff, authorize board mutations, or change `.tasks/`.

`.agents/.agent-toolkit.json` records each installed file's hash and the catalog
revision and digest for all 27 refreshed or newly installed artifacts. The two
existing MCP definitions retain their existing ledger entries.

Eight JSON Schemas live in `.agents/schemas/`: `adr`, `architecture`, `design`,
`idea`, `research`, `spec`, `threat-model`, and `verification`. Schema installation
does not install a document validator or prove existing documents conform.

The `toolsmith` agent and its host adapters are also installed. Its updated
memory policy uses project scope. Existing `context7` and `github` MCP definitions
are retained; this change installs no additional external MCP integration.

The canonical skill names replace `spec-authoring` with `write-spec`,
`adr-authoring` with `record-decision`, `architecture-docs` with
`document-architecture`, and `threat-model-authoring` with `model-threats`.
Use the new names when routing work.

## Local setup

Codex and OpenCode discover portable skills from `.agents/skills/`. Claude's
skill copies and all three hosts' agent definitions are generated by `lexicon
sync`; generated files stay local under `.claude/`, `.codex/`, and `.opencode/`.
The tracked sources are the review surface.

For a reproducible render, use a Lexicon checkout at the revision linked above
with Python 3.12 or later and `uv` available. From the Pantheon checkout:

```sh
LEXICON_CHECKOUT=/path/to/lexicon
export LEXICON_CATALOG_ROOT="$LEXICON_CHECKOUT"
uv run --project "$LEXICON_CHECKOUT" --frozen lexicon sync --project .
uv run --project "$LEXICON_CHECKOUT" --frozen lexicon doctor --project .
```

Run this local activation only when authorized for the target checkout. Sync
renders host instructions, the OpenCode memory plugin, and the Codex toolsmith
memory MCP registration. It can update the tracked MCP ownership ledger as well
as ignored host configuration. Inspect those changes before including anything
in a later PR. This setup PR prepares sources only; its host rendering is tested
in a disposable copy, without changing the running app or active host settings.

Toolsmith memory needs separate local activation. The generated Codex registration
launches `lexicon-memory-mcp` by name: that executable must be on the Codex
process's `PATH`, with Lexicon's optional `mcp` extra installed in the executable's
Python environment. Running the base CLI through `uv run` does not establish
either prerequisite for a separately launched host. Until an authorized local
installation provides them, Codex toolsmith memory is unavailable even if sync
succeeds. Memory directories also need scaffolding; `doctor` reports that gap.
The portable lifecycle skills and schemas do not depend on this memory service.

`doctor` reports wiring and host availability. Its default successful exit code
can include degraded checks; read the reported statuses. Rendering is not an
end-to-end test of skill selection, execution by a host, or a memory-server launch.

## Verify and update

With the same catalog environment, inspect freshness and schema resolution:

```sh
lexicon update --check --project .
lexicon schema list --project .
lexicon schema path verification --project .
```

These shorter commands assume the installed `lexicon` CLI supports this catalog;
the `uv run --project "$LEXICON_CHECKOUT" --frozen` prefix selects its pinned CLI
when needed. Freshness is relative to the selected catalog, not automatically to
GitHub's newest revision. `lexicon validate` validates that catalog, not every
document in Pantheon.

For an update, use a separate review branch, select the intended catalog revision,
and review the source and provenance diff. Use `lexicon update` for existing
names; handle renamed packages explicitly so old copies do not remain active.
Validate the catalog, check installed hashes, render hosts in a disposable copy,
and follow [CONTRIBUTING.md](../../CONTRIBUTING.md) for review and delivery.

Known upstream limitation: the PR-feedback helper's viewer lookup can fail with
the worker App's authentication ([Lexicon #260](https://github.com/G-Hensley/lexicon/issues/260)).
Use the skill's manual fallback with the same worker identity when affected;
installing this catalog does not resolve that upstream issue.

Archify's bundled preview also uses a synchronous browser launcher, which can
briefly block its HTTP/SSE loop while the opener runs. Use `preview --no-open`
with the usual diagram arguments and open the printed URL manually when this
matters. [Lexicon #282](https://github.com/G-Hensley/lexicon/issues/282) tracks the
catalog follow-up; this proposal keeps the pinned renderer unchanged.

`pnpm test:skills` checks the installed opener's URL rejection and process-result
handling without launching a browser. It runs in frontend CI and as part of
`pnpm test`. These consumer checks live outside `.agents/`, so catalog updates
preserve them. They do not replace Archify's complete upstream preview suite.
